## 技术核对

- `ri_triggers.c` / `RI_FKey_check`：普通外键检查查询父表并取得 `FOR KEY SHARE`；正文限定普通非延迟外键，不扩展为所有约束的执行时机。
- Explicit Locking：KEY SHARE 互相兼容，冲突删除和键值更新。普通示例锁保持到事务结束；保存点回滚等特殊路径未纳入本例。
- `multixact.c`：offsets 与 members 分工、lock-only 记录的旧成员跳过条件、`MultiXactIdExpand` 创建新集合而非原地修改。说明数据库按可能仍活跃的成员边界判断，不把事务年龄直接等同于缓存压力。
- `slru.c` 与 MultiXact 读取路径：16 页 bank、页号取模、bank 锁及相关排他访问。扩大缓存增加组数，但不保证同页访问并发，也没有消除 MultiXactGen 等共享状态竞争。
- PostgreSQL 17 发布说明及 18 参数文档：两项参数从 17 可配，17/18 默认 member=32、offset=16，不随 shared_buffers 自动缩放；启动生效、16 页倍数。
- PostgreSQL 18 监控文档：`pg_stat_slru` 为实例级累计统计；增量采样检查 stats_reset、避免长监控事务中的统计快照。SLRU 文件读取与物理设备读取分开表述，相关 wait event 只作为关联证据。
- [bd8d9c9bd](https://github.com/postgres/postgres/commit/bd8d9c9bd)：19 的 MultiXactOffset 扩展为 64 位，8 KB 页偏移项数量减半；MultiXact ID 仍是 32 位，成员布局未同样扩展。没有沿用原文“所有配置一律翻倍”的建议，也没有声称整个 MultiXact 已无回卷限制。
- 官方依据集中到文末，正文保留操作安全所需的重启、事务原子性和监控权限条件。

## 最小实验

使用现有 PostgreSQL 18.4（Homebrew）二进制，macOS aarch64。`maintenance/107-verify.py` 创建临时 UTF8、无 locale、32 MB shared_buffers 实例，只监听私有临时目录的 Unix socket，不监听 TCP，不访问现有数据库。结束或失败时停止实例、清理目录及会话。

复现入口：

```sh
python3 maintenance/107-verify.py --pg-bin /opt/homebrew/opt/postgresql@18/bin --check-output
```

脚本直接提取正文 13 个具名 SQL 块，创建独立 mx_demo schema、两条客户数据（Alice、Bob），由 A、B、C 三个独立会话插入引用 Alice 的订单，第四个观察会话保持自动提交。逐项执行建表、样例数据、写入、观察、提交、核对与清理，以及两段诊断 SQL。观察会话直接执行正文的 psql `\gset`，保存并复查旧 MultiXact ID，避免自动脚本与读者步骤分开维护。

补全后的例子在 PostgreSQL 18.4 连续两次运行通过，第二次启用 `--check-output` 逐块核对正文 8 组结果（忽略行末空白，保留数据及行数）：A=756、B=757、C=758；Alice 的 xmax 从 0 变为事务 ID 756、MultiXact 1，再变为 MultiXact 2；成员由 A/B 变为 A/C，旧编号 1 仍保留 A/B；Bob 的 xmax 始终为 0。

提交后 orders 为 100/1/100.00、101/1/200.00、102/1/300.00 三行，Alice 的 xmax 仍为 2，确认事务结束不要求立即清零行头部。正文实际输出来自本次新建 schema 后的实验，替换初稿仅有结果表的三会话例子；事务 ID 因增加 schema DDL 与初稿不同，机制没有变化。

脚本另确认默认 member=32、offset=16，单位 8kB，上下文 postmaster；正文统计查询返回两种 SLRU，事务查询准确返回仍打开的 A、C；执行正文 DROP SCHEMA 后检查对象确已移除。两次运行结束均清理临时实例，未修改本机已有服务。

验证范围仅为外键兼容行锁、MultiXact 成员变化和诊断语句，不覆盖大工作集缓存换入、并发 bank 锁等待或吞吐收益。未把启动时 SLRU 读取的非零累计值当成故障证据，也没有执行生产调参或重启。
