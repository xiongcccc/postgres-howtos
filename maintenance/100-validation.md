# 第 100 篇验证记录

日期：2026-09-10。数据库：PostgreSQL 16.14（Homebrew）。使用独立临时集群，仅开放 Unix socket；测试自动停库、清理，不读取或修改现有业务数据库。

## 实际通过的检查

| 项目 | 结果 |
| --- | --- |
| 通知事务回滚 | 接收者没有收到回滚事务的消息 |
| 同事务重复通知 | 相同 channel、相同 payload 的两次通知只收到一次 |
| payload 边界 | 7999 字节 ASCII payload 成功，8000 字节失败 |
| 诊断 SQL | 活跃等待、特殊对象锁、触发器列表、队列占用查询均可执行 |
| 持久事件示例 | 回滚不留事件；唤醒成功后事件仍为待处理，没有提前确认或删除 |
| 队尾时序 | 发送者完成扫描但尚未提交时，另一事务入队、抢锁失败并提交；发送者结束后队尾仍保留 |
| 过期过滤 | DELETE RETURNING 删除旧记录，外层时间过滤返回 0 条；记录确实不再存在 |
| 提交锁作用域 | 数据库 A 的发送事务持锁并等待 SyncRep；数据库 B 的不同 channel 发送事务等待相同对象锁 |

## 如何复现

在仓库根目录执行，路径指向包含 initdb、pg_ctl、psql、createdb 的 PostgreSQL 安装目录；不要以 root 运行：

```bash
python3 maintenance/test_notify.py --pg-bin /path/to/postgresql/bin
```

脚本直接提取第 100 篇标记的 SQL 来验证。队尾与过期行为另有最小模型，模型依据演讲公开片段构造，不是讲者完整的生产触发器。

为了可控地观察持锁状态，测试只在临时集群中设置一个不存在的同步备库名称，制造 SyncRep 等待；观察完后恢复配置，使事务正常完成。没有搭建真实备库，也没有用取消 COMMIT 的方式假定业务回滚。

## 边界

- 源码基线为 PostgreSQL `REL_16_14` 的 `src/backend/commands/async.c`，不是对全部版本的断言。
- 未做吞吐压测、真实同步复制、网络断连、崩溃恢复或端到端消费确认测试。
- UNLOGGED 的故障恢复和复制限制依据官方文档，本次未进行崩溃实验。
- outbox 仅验证表和唤醒语义，不是完整的多消费者消息队列，没有承诺 exactly-once。
- 原演讲的性能结果与本地功能验证分开，不编造性能倍数。
