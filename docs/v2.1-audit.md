## 不作为缺陷的项目

已有搜索引擎支持标题、原题、别名、正文和多关键词 AND；九组要求关键词均有相关命中。已有复制直接取 code.textContent，手机表格局部滚动、深色配色、图片比例与图表按需加载已通过浏览器测试，不重新开发。

跨专题数量差异不是漏文：主归属数量合计 109，全部关联收录合计 129，14 篇文章属于多个专题。不硬编码计数，也不删关联分类。

## SEO 判断与边界

JavaScript 不等于不能被索引。Google 可以渲染 JavaScript；这里的具体限制是不同文章共用一个 HTTP 资源、仅用 fragment 区分内容，以及初始 canonical 不随文章变化。没有 Search Console 权限，不能从这些证据推断当前实际收录量。

优先保留技术栈，为全部编号文档生成普通目录下的 index.html；仓库已有 .nojekyll，GitHub Pages 可以直接托管这些文件，不需要服务端 rewrite。静态内容与交互内容来自同一份原文和元数据，不做爬虫识别或专用内容。

参考：[Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)、[URL 结构](https://developers.google.com/search/docs/crawling-indexing/url-structure)、[GitHub Pages 静态托管](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

## 待验证而非既定缺陷

原计划核验的失败状态、目录刷新、QR 延迟加载、静态代码保真、无 JavaScript 阅读、焦点及布局偏移均已进入专项测试。具体证据见本轮交付报告。

早期 200ms 的目录刷新检查发生在 Docsify 的 500ms 滚动动画中途，不能据此断定锚点失效；报告以动画完成后的最终位置为准。随后也确认了 doneEach 插入内容导致的额外偏移，两者是不同问题。
