## 保留与边界

保留 V2 的首页结构、白色/中性深色底、深蓝与青绿交互、九个专题、六条路径及 Docsify。没有迁移框架，没有注册服务，没有增加后端，也没有引入前端包管理或字体网络请求。

`data/articles.json`、109 篇编号 Markdown、技术图片、CNAME 和 .nojekyll 均未修改。108 篇技术文章与一篇项目后记保留；来源、署名、验证记录和 SQL 语义不变。新增的是展示层和构建产物，不是文章改写。

原有 `#/docs/编号`、`.md` 形式、章节参数、首页 `#/README`、`#/README.md` 和作者锚点继续可用，不强制跳到新 URL。

## 实际修改

### 可发现的静态文章

- 同一轮目录构建生成 109 个 `/articles/编号/index.html` 和一个静态文章目录。合计约 4.20MB，生成文件不手工维护。
- 初始响应即包含中文标题、正文、来源、版本说明、原文引用、代码高亮、表格、目录、文末导航、自引用 canonical 及 JSON-LD。
- 禁用 JavaScript 时仍可阅读正文、展开原生目录、访问上一篇/下一篇和来源。Mermaid 此时保留文本源代码；启用 JavaScript 后才按需绘图。
- Sitemap 从根入口扩展为 111 个普通 URL：首页、静态目录及全部编号文章。不填写 fragment URL，不编造更新时间。
- 首页初始 HTML 的页脚和无脚本入口直接链接静态目录，目录以普通 a 标签列出全部文章，不依赖爬虫先执行搜索。
- 旧 Hash 文章动态设置对应的静态 canonical；根 HTML 不再硬编码一个会与文章冲突的 canonical，首页渲染后设置根地址。内部搜索和辅助 Hash 页面使用 noindex,follow，不将搜索状态当成独立文章。
- `article-view.js` 由 Node 与浏览器共享标题、元数据、代码类型、结构化数据和相关文章逻辑，避免两套内容来源。

### 阅读细节

- 正文上限由 880px 收至 840px，保留默认 16px 中文正文，行高 1.85；不把长文放大成营销页。
- 较长的“主题：说明”标题在桌面按语义分行，避免在“性能”等词中间断行；文字本身和原锚点保持不变。
- 代码默认由桌面 13px/手机 12px 调整到 14px/13px。统一 SQL、shell、sh、conf 的语法别名，复用现有 SQL、Shell、C、INI 等组件。
- EXPLAIN 和混合 psql 输出保留等宽原文，不给执行计划强制折行，也不靠高亮颜色干扰树形结构。宽 SQL 与表格继续在局部滚动。
- 静态 HTML 用字符实体保存行尾空格，避免 Git 空白告警；浏览器解码及复制后的字符仍与原文一致。
- 复制、目录与页脚按钮保持适当触控尺寸；手机目录默认收起，展开后的目录列表限制高度，可在列表内滚动。
- 桌面和手机分别记住本次浏览中的目录手动展开选择。跨断点时采用对应布局的默认/手动状态，不把桌面展开状态直接带到手机。
- Docsify 在 doneEach 之前计算锚点，插入中文标题、元数据和目录后目标位置会变化。现在使用固定版本现有定位机制重新计算，并统一 88px 顶栏偏移。静态页使用原生章节链接与增强后的定位。
- 文末保留同主专题上一篇/下一篇、最多三条按实际专题关系生成的延伸阅读、当前专题、源文件与纠错入口，不增加随机推荐。

### 导航、统计与检索

- 主要入口统一为“首页、专题、学习路径、全部文章”。旧 URL 不随命名改变。
- 侧栏始终展开当前文章的主专题，其他专题尊重读者手动状态。当前文章可见时不重置滚动位置，不可见时才定位。
- 侧栏明确“主归属文章”，专题页同时显示全部关联收录与主归属数量。首页含跨专题收录；搜索筛选也采用全部关联主题。
- 各数字从元数据计算：主归属总计 109，关联收录总计 129，14 篇属于多个专题。不通过硬编码让不同口径表面相等。
- 首页第三项指标改为真实的六条学习路径。路径编号、文章数、不重复引用、目的地及现有阅读顺序已核对，没有擅自改写路径内容。
- 保留现有搜索引擎。修复请求失败后手动删空查询仍残留重试按钮的状态；正常状态不显示错误恢复控件。
- 搜索框 Escape 可收起高级筛选；阅读设置 Escape 关闭并恢复焦点。手机抽屉打开后，页头、正文和页脚均不能被后台 Tab 访问。

### 首页加载与仓库介绍

- 发现首页首帧曾先按文章页显示侧栏布局，再切换宽首页；搜索框插入也会挤动内容。现在首次绘制前确定页面类型，预留加载及搜索空间，内容完成前不提前显示页脚。图标启用时保留布局尺寸。
- GitHub README 改为简洁的项目定位、在线入口、专题、路径、最近收录、来源及贡献说明。文章链接使用完整在线 URL，避免 GitHub 将 `/docs/编号.md` 当成站点根路径。
- 网站首页单独生成到 `docs/home.md`，仍从 `maintenance/home-template.md` 编辑；README 从 `maintenance/readme-template.md` 生成。原 `#/README` 通过 Docsify 别名显示网站首页。

## SEO 判断与验证

JavaScript 网站不等于无法被索引。Google 可以执行 JavaScript，但 fragment 不是稳定的独立文章抓取入口。本轮解决的是初始内容、普通链接、独立 HTTP 资源、canonical、Sitemap 与结构化数据，不宣称已有文章曾经“完全不能收录”，也不虚构收录增长。

没有改成 History API 路由，因为普通目录下的静态文件即可由现有 GitHub Pages 托管，无需 rewrite，也无需让历史链接失效。没有迁移到 Astro、Next.js 或 VitePress；这次所需能力已由小型构建步骤提供。

实际验证包括：109 个静态 URL 均返回 200；禁用 JavaScript 后标题、代码和原生目录正常；静态目录能发现全部文章；canonical 与 JSON-LD 与元数据一致；原文内跨文章章节链接的目标存在；不存在的静态编号返回真实 404。以上为本地 HTTP 服务与 Chrome 验证，不代替生产环境发布验收。

依据：[Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)、[Google URL 结构](https://developers.google.com/search/docs/crawling-indexing/url-structure)、[GitHub Pages 静态托管](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。搜索引擎最终选择的 canonical、发现时机与收录情况仍须上线后观察。

条件：本地 HTTP、独立桌面 Chrome、1440/390px 宽度、1000px 高度、无 CPU/网络限速，内容出现后观察 1 秒，屏蔽访问统计。每个场景单次观察，仅用于查找回归：

| --- | ---: | ---: |
| 首页 1440px | 112ms | 0 |
| 首页 390px | 100ms | 0 |
| 静态逻辑复制文章 1440px | 80ms | 0.0102 |

本轮迭代曾测到首页 CLS 约 1.13，LayoutShift.sources 指向初始容器/页脚/搜索插入；修复后上述两种宽度均为 0。它们不是公网、真机或 28 天真实用户 Core Web Vitals。没有测量现场 INP。

九次本地有缓存的搜索界面响应为 134–153ms，包含 120ms 输入防抖；不把它们当成网络延迟或现场 INP。

两份 CSS 合计约 32KB，比 V2 略增；共享视图模块约 4.4KB。新增约 8.1KB 的 Prism core/clike 仅用于构建。静态页面不下载 Docsify、Marked 或浏览器高亮引擎；含图文章仍需按需下载约 3.34MB 的 Mermaid，不能将这类文章宣称为小资源页面。首页没有加载 Mermaid 或全文索引。

正文、次要文字、品牌/交互链接和代码基础色在两种主题下满足已有 4.5:1 对比度测试。原生 details/dialog、语义目录、焦点、跳至正文、键盘与触控检查通过。CSS 动效遵守 reduced motion；旧 Hash 锚点仍沿用固定版本 Docsify 的约 500ms 滚动动画，未改写第三方库。这不是完整 WCAG 2.2 AA 认证。

## 维护与剩余风险

- 所有生成文件仍通过同一条 build-catalog 命令更新；没有第二套文章数据。修改模板、脚本、样式后都应重新构建，避免静态 HTML 中的资源摘要过期。
- 静态 HTML 增加约 4.20MB 仓库体积，后续样式/脚本修改会使生成页的资源摘要同步变化，这是兼容现有无额外部署构建方式的取舍。
- 本报告的本地验收不能证明新静态地址在实际域名返回正确内容，仍须发布后核验；也没有 Search Console 的实际抓取与收录数据。
- 真机 Safari/微信浏览器、真实慢网与长期访问指标未覆盖；远程历史图片的长期可用性及二维码时效不能由本轮保证。
- 原有 Gitalk OAuth 凭据撤销仍需维护者在 GitHub 处理；此前移除前端配置不会清除历史版本。没有恢复站内 OAuth 登录。
- 后续升级 Docsify 时，需要重新核对其生命周期与锚点定位机制；本轮已固定版本并添加刷新回归。
