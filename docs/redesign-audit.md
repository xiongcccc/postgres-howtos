# 全站设计与工程审计

审计日期：2026-10-23。范围：当前工作树、线上静态入口、1440px 与 390px 浏览器基线。改版前截图见 [redesign/before](redesign/before/)。

## 架构与内容基线

- Docsify 4 浏览器端渲染 Markdown，GitHub Pages 静态发布；没有应用构建服务或运行时后端。当前 CI 执行目录测试及 diff 检查。
- `data/articles.json` 是唯一文章目录，`maintenance/build-catalog.mjs` 生成首页、侧栏、专题、路径、系列、会议、全文索引及资源版本。`scripts/reading.js` 增强搜索、中文标题、折叠侧栏和 TOC。
- 109 篇编号文档均有对应元数据：108 篇技术文章、1 篇项目后记。9 个专题的主归属计数总和为 109；多专题计数总和为 129，14 篇有交叉收录。首页排除后记、侧栏包含后记，原界面的差异来自不同口径，不是缺文。应统一从目录派生并区分技术文章、后记和专题收录。
- `#/docs/编号`、`#/README`、专题锚点及筛选参数都是实际 Hash 路由；必须保留。未发现遗漏的编号文档。完整内部链接和路由回归在实施后复查，不能把外部引用全部认定有效。
- 上游来源、作者、版本与验证记录完整保留；本次不修改编号文章正文、SQL、测试输出或技术图片。

## 问题与优先级

| 严重度 | 问题与依据 | 影响 | 处理方向 |
| --- | --- | --- | --- |
| 高 | 首页长篇英文个人简介、课程、作品与知识库内容混排；390px 首屏搜索靠后 | 第一次访问难以进入查找任务 | 压缩品牌介绍，将搜索、问题、专题、学习路径置前；保留简洁维护者与个人主页链接 |
| 高 | 根入口额外展示整屏封面，与 README 首页重复 | 多一次点击；专题曾被封面遮挡 | 根入口与 README 直接展示同一可搜索首页；历史封面文件保留，不改文章路由 |
| 高 | `custom.css` 1049 行、`reading.css` 105 行，深色覆盖多次使用 `!important` | 层叠难维护，曾出现深色宽度和表格回归 | 重建统一 light/dark tokens、版式与组件边界，保持同一布局模型 |
| 高 | 搜索三个筛选并列；归一化查询与正文摘要使用不同匹配方法；没有高亮、清除筛选、结果键盘导航 | 用户难判断命中位置，手机首屏被筛选占用 | 主题优先，系列与来源进入高级筛选；一致的摘要定位、高亮、安全 DOM 渲染、清除与恢复 |
| 高 | 首页未直接展示专题与路径全貌，主要依赖跳转 | 可探索性不足 | 数据生成九专题轻列表、真实路径及近期文章元数据 |
| 高 | 夜间模式依赖远程 latest 插件及轮询，阅读控制原为 span 模拟按钮 | 状态不稳定、键盘和触摸体验不一致 | 本地主题/字号控制，原生 button、系统偏好、持久化与减少动效 |
| 高 | 移动侧栏主要依赖 Docsify 默认行为，缺少完整焦点管理 | 菜单可能遮挡内容或让焦点落到背后 | 明确抽屉、遮罩、Escape、焦点约束与回到触发按钮 |
| 高 | Gitalk OAuth 配置包含浏览器可见的 client secret | 公开凭据不应被当作安全服务端秘密；历史提交仍含旧值 | 去除网页内嵌 OAuth 凭据，使用既有 GitHub Issues 的讨论/反馈入口；建议维护者另行轮换旧凭据，不能通过删文件声称历史泄露已消除 |
| 中 | 顶栏、侧栏、角标重复 GitHub 入口，阅读控件与统计/赞赏悬浮在正文周围 | 注意力分散、手机内容被覆盖 | 固定简洁品牌顶栏；附属入口与统计移到文末，不悬浮覆盖正文 |
| 中 | TOC 仅收录 H2/H3，IntersectionObserver 只取本次进入项 | 长篇文章目录不完整，滚动高亮可能丢失 | 收录 H2–H4，统一锚点偏移，按当前位置计算当前章节 |
| 中 | 缺少面包屑、关联文章和明确的源码/纠错入口 | 阅读后难以回到知识结构 | 稳定使用第一个 topic 为主归属；专题内上下篇与相关项可追溯 |
| 中 | 代码插件和语言高亮依赖多个无固定版本 CDN；EXPLAIN 和表格不能破坏空格 | 首屏请求多、复制内容可能夹带装饰 | 固定必要依赖，原生复制纯 code.textContent；保留局部横滚，补 SQL/bash/python/json 高亮 |
| 中 | 小尺寸品牌图仍请求约 631KB 原图；首页远程作者 SVG 和二维码占据大量空间 | 增加首屏与滚动成本 | 复用已有小尺寸品牌图，保留原图与二维码但按需展示；为图片保留尺寸与懒加载策略 |
| 中 | Hash 页面无独立服务端 HTML；抓取入口只返回加载提示；没有 sitemap/robots | 搜索发现和分享预览受限 | 优化页面 title/description/结构化数据与可抓取项目入口，补真实 sitemap/robots；明确 Hash 索引限制，不伪造每篇可索引页面或未经授权迁移 URL |
| 中 | 赞赏弹窗未完整约束 Tab 焦点；焦点样式和触摸尺寸分散 | 键盘与辅助技术障碍 | 原生 dialog、焦点恢复、统一 focus-visible、44px 主要触摸目标 |

## 实施决策

保留 Docsify 和静态目录生成器，无新服务、无账号注册、无框架迁移。按审计、设计基础、首页、检索导航、阅读体验、响应式/无障碍、实测验收连续推进。

白色页面、墨色正文、深蓝品牌与少量青绿交互；用排版和分割线组织内容，不制作营销式 Hero 或大卡片墙。字体优先 Inter / Noto Sans SC / JetBrains Mono，但提供系统栈，不强制下载大体积中文字库。

## 验收方法

- 目录生成一致性、109 篇元数据与路由、旧锚点、筛选组合、清除/重载/前进后退、全文加载失败/重试与显示更多。
- 1440、1280、1024、768、390、360px 实际浏览器；首页、专题、搜索、不同结构文章、404、抽屉、浅/深色、宽 SQL 和表格。
- 修改前后对照截图；记录实际网络请求、静态资源大小及可重复的本地时间测量。没有真实用户遥测时不宣称达到 LCP/INP 等现场指标。
- Google 对 Hash 路由的限制依据：[JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)。交互参照 [WAI-ARIA 对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)，自动化检查不等于完整 WCAG 认证。
